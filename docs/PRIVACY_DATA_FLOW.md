# ConnectHub Privacy and Data Flow

Status: **current implementation documented; legal/privacy approval NOT GRANTED**

## Data inventory

| Data | Stored in PostgreSQL | Sent to browser | Sent externally |
|---|---|---|---|
| Username, email, display name | Yes | Own account; public username/display name as needed | No by default |
| Password | Argon2id hash only | Never returned | No |
| Session | SHA-256 digest, expiry, timestamps | Random token in HttpOnly cookie; CSRF token in readable cookie | No |
| Rooms/memberships | Yes | Authorized room/member views | No |
| Message content | Yes | Authorized members over HTTP/WebSocket | Gemini only when AI is enabled for summary/embedding |
| Notifications/read positions/presence timestamps | Yes | Owning/authorized user | No |
| Summaries/embeddings/jobs | Yes when AI enabled | Authorized members/owners | Generated by configured provider |

## Core flows

The browser sends credentials only to the same-origin API/proxy. PostgreSQL is the durable source of truth. WebSocket events carry authorized room/user data to authenticated members. Logs use request IDs and should not contain tokens or message bodies.

## AI boundary

AI is disabled by default. Enabling it sends selected room messages or search text to Gemini over HTTPS and stores resulting summaries/vectors locally. Users need clear notice before this occurs. Provider account tier, logging, retention, region, deletion, and subprocessor terms must be reviewed.

Google's Gemini API terms effective 2026-03-23 distinguish unpaid and paid services. Unpaid services may use submitted content and responses to improve products and may involve human review; they instruct users not to submit sensitive, confidential, or personal information. Paid Services do not use prompts/responses to improve products, but Google documents abuse-monitoring retention and possible processing in countries where Google or its agents maintain facilities: <https://ai.google.dev/gemini-api/terms>. The current abuse-monitoring documentation states a 55-day retention period unless an approved zero-data-retention arrangement sanitizes the logged content: <https://ai.google.dev/gemini-api/docs/usage-policies> and <https://ai.google.dev/gemini-api/docs/zdr>. Optional developer logging has a configurable 7, 14, 28, or 55-day project retention and datasets can persist beyond that: <https://ai.google.dev/gemini-api/docs/logs-policy>.

ConnectHub uses `generateContent` and `embedContent`; it does not use Gemini Files, Interactions, explicit caching, Search/Maps grounding, or provider datasets. Do not enable optional provider logging, create datasets from user messages, use an unpaid tier with real pilot data, or claim zero retention without explicit owner/privacy approval and current provider evidence.

### Backlog and transmission policy

With AI disabled, ordinary messages do not create embedding jobs and cannot later become an automatic historical backlog merely because `AI_ENABLED` changes. New messages are eligible only when both AI and automatic indexing are enabled for that process. Existing messages require the bounded owner route plus the separate `AI_BACKFILL_ENABLED` deployment gate. These controls are operator safeguards, not proof of each participant's consent; an approved notice/legal basis remains required. Semantic queries and selected summary messages are transmitted only when a member explicitly invokes those enabled features. Synthetic benchmark fixtures never contain production chat.

## Retention and deletion gaps

Account deletion/export, room retention policy, message deletion, legal hold, backup expiry, notification retention, and AI-derived-data erasure are not implemented product workflows. Room deletion cascades current live room data, but provider backups follow their own retention. These are policy/product decisions required before a public launch involving real users.

## Data-subject and operator controls

Before public release, define privacy notice, lawful basis/consent, age policy, support contact, access/export/correction/deletion workflow, breach response, retention periods, subprocessor list, data residency, and backup deletion. This document is engineering evidence, not legal advice.
